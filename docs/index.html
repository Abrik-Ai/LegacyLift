Silent Bugs Caught — Why Find-and-Replace Fails

These three constructs are syntactically valid in both Python 2 and Python 3, so a naive text substitution would not touch them — yet each silently changes program behavior.

zip() returns an iterator

In Python 2, zip() returns a list. In Python 3 it returns a lazy iterator — consumed once. Code that calls len() on the result or indexes into it raises TypeError at runtime, not at import time. A search-and-replace on zip( would blindly wrap every usage, missing the cases where the iterator is only iterated once (which are safe) and breaking only the ones that re-use the result. LegacyLift identified all three unsafe call sites (ML-3, ML-4, ML-5) and added list() wrappers precisely.

Bare print statement

A bare print with no argument is legal in Python 3 — it parses as an expression referencing the built-in function and does nothing. In Python 2 it emits a blank line. Find-and-replace targeting print "…" patterns would never touch a bare print, silently suppressing blank-line output in Python 3. Issue N2-8 catches and fixes this with print().

Integer division 3 / 2

eta / len(mini_batch) is valid syntax in both Python versions. In Python 2, 3/2 == 1 (floor division); in Python 3, 3/2 == 1.5 (true division). A find-and-replace can't know whether the surrounding context has integer operands, so it cannot safely add a float() cast everywhere. LegacyLift analyzed each occurrence and documented the change as intentional — the golden files capture both behaviors and two xfail tests pin the decision.

Integer-Division Decision

Detected · Documented · Intentionally fixed

eta / len(mini_batch) appears in four places across network.py (lines 80, 82) and network2.py (lines 204, 206). When eta is an integer and len(mini_batch) is 2, Python 2 computes 1 (floor division) while Python 3 computes 1.5 (true division).

The task specification designates this as an intentional behaviour change: Python 3's true-division semantics are numerically correct for a gradient-descent learning rate update. No float() cast was added — the Python 3 default is already correct. The legacy floor-division result is preserved in two golden files and documented with @pytest.mark.xfail(sys.version_info >= (3,), strict=True), which records the divergence on every future run without hiding it.

The float-eta variants of the same tests (test_update_mini_batch_float_eta) pass identically on both Python versions because floating-point division was always true division in Python 2 when either operand was a float.

network3.py — Out of Scope

Hard dependency on Theano (archived 2017, last release 2020)

network3.py has a hard dependency on Theano, a library that was archived in 2017 and does not support Python 3.8+. Migrating this file would require a complete backend rewrite (e.g., to PyTorch or TensorFlow), which is outside the scope of a syntactic/semantic upgrade. All other issues in the file (cPickle, xrange, print statements) are moot given the Theano blocker. The file is excluded from the deprecated-usage counts and test suite.
